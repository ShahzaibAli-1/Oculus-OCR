SLIDE 6 — ETHICAL DECISION MAKING
────────────────────────────────────────────────────────────────
HEADING:  A Real Ethical Decision We Faced

THE DECISION:
  Speed vs. Quality — Should we skip image preprocessing
  to make the app faster?

OPTION A (Speed):
  Skip denoising/deskewing → faster output → lower accuracy

OPTION B (Quality — our choice):
  Full preprocessing pipeline → slower → significantly more
  accurate OCR, especially on handwritten/noisy images

WHY QUALITY WON:
  Inaccurate output misleads users. Speed is never worth
  producing wrong information.

SLIDE 10 — ETHICAL DECISION PROCESS (4-STEP MODEL)
────────────────────────────────────────────────────────────────
HEADING:  4-Step Ethical Decision Process — Applied

STEP 1 — IDENTIFY THE ISSUE:
  User images may contain private or confidential content.

STEP 2 — ANALYZE STAKEHOLDERS:
  Users (privacy at risk) · Developers · OpenAI (API recipient)

STEP 3 — EVALUATE ALTERNATIVES:
  A) Send image to GPT-4o API — convenient, less private
  B) Local OCR only — private, less intelligent
  ✅ C) Hybrid — local OCR first, API only for structure analysis

STEP 4 — JUSTIFIED DECISION:
  Hybrid approach chosen. Cybersecurity risk minimised —
  full images are encoded in-memory, never saved to disk.
  Vulnerability: API key leakage → mitigated via .env file.

SLIDE 17 — COMPUTER CRIMES & RISKS
────────────────────────────────────────────────────────────────
HEADING:  Security Risks Specific to Ocular

RISK 1 — DATA THEFT
  User uploads may contain confidential documents.
  Risk: API interception during GPT-4o Vision call.
  Mitigation: HTTPS enforced by OpenAI SDK; no raw storage.

RISK 2 — MISUSE
  Someone could use Ocular to extract text from private
  documents they do not own (copyright/IP violation).
  Mitigation: Terms of use must prohibit unauthorised use.

RISK 3 — API KEY COMPROMISE
  Exposed OPENAI_API_KEY = financial and data risk.
  Mitigation: Stored in .env, never committed to version control.

RISK 4 — OVER-RELIANCE
  Users treating 70% confidence output as 100% accurate.
  Mitigation: Confidence score displayed on every result.

STATIC LOGIC:

SLIDE 24 — AGENT TYPE SELECTION
────────────────────────────────────────────────────────────────
HEADING:  Why We Chose a Goal-Based + Learning Agent

GOAL-BASED:
  The agent always works toward one clear goal:
  "Produce the most accurate, best-formatted Word document."
  Every decision (preprocessing level, confidence threshold)
  is made to maximise that goal.

LEARNING:
  The agent stores every result in SQLite.
  User feedback (👍/👎) is recorded and associated with outcomes.
  Historical confidence averages inform future decisions.

WHY NOT FULLY AUTONOMOUS?
  Document conversion has legal/professional consequences.
  A human must review and approve the final output.
  → Semi-autonomous is the correct and responsible choice.

SLIDE 25 — OPERATIONAL WORKFLOW
────────────────────────────────────────────────────────────────
HEADING:  Observe → Interpret → Decide → Act → Learn

5-STEP CYCLE:

  1. OBSERVE
     Perception Agent reads the image, runs OCR,
     measures confidence (e.g. 68%)

  2. INTERPRET
     Analysis Agent sends image to GPT-4o Vision.
     GPT-4o returns structured JSON: headings, body, alignment.

  3. DECIDE
     Orchestrator checks confidence. If < 60%:
     trigger aggressive preprocessing before re-OCR.

  4. ACT
     Formatting Agent + Document Agent generate the .docx
     with proper styles, colours, spacing.

  5. LEARN
     Memory Agent stores result + processing time + feedback.
     Next run benefits from historical context.

SLIDE 27 — MEMORY & CONTEXT
────────────────────────────────────────────────────────────────
HEADING:  Ocular's Memory System

SHORT-TERM MEMORY (session):
  → Python dictionary, lives in RAM
  → Stores: current image name, OCR confidence,
    preprocessing decision, GPT-4o analysis result
  → Cleared when application closes

LONG-TERM MEMORY (persistent):
  → SQLite database (data/memory.db)
  → Stores: every document processed, confidence score,
    formatting decisions, user feedback, processing time
  → Survives restarts — enables learning across sessions

HOW IT HELPS:
  Agent uses historical avg confidence to calibrate
  how aggressively it preprocesses new documents.

SLIDE 30 — ETHICAL AGENT DESIGN
────────────────────────────────────────────────────────────────
HEADING:  Ethics Built Into Ocular's Agent Design

PRIVACY:
  User images processed locally (OpenCV + Tesseract).
  Only structural analysis (not raw image content) sent to API.

BIAS:
  Rule-based fallback avoids over-reliance on GPT-4o.
  Confidence score shown so users can spot errors.
  Works for printed AND handwritten documents.

TRANSPARENCY:
  Every agent decision is logged with timestamp and reason.
  "View Log" button shows full explainability report.
  Confidence score printed in the Word document header.

USER CONTROL:
  No automatic saving. No cloud sync. No telemetry.
  The agent works for the user — not the other way around.

SLIDE 32 — SAFETY MECHANISMS
────────────────────────────────────────────────────────────────
HEADING:  How Ocular Stays Safe & Accountable

LOGGING:
  Every agent action logged with timestamp, agent name,
  and message. Stored in /logs/ as rotating .log files.
  Users can audit exactly what happened and why.

OVERRIDE:
  Graceful fallback — if GPT-4o API fails, rule-based
  analysis runs automatically. System never crashes silently.
  User is always informed of which mode was used.

EXPLAINABILITY:
  "View Log" button renders the full decision trail.
  Word document header shows confidence score.
  Agent labels its own output: "GPT-4o" or "Fallback (rules)".

FINAL SAFETY PRINCIPLE:
  Ocular is designed so that a user who does not trust
  the AI output can always verify, override, or ignore it.
  The agent advises — the human decides.
