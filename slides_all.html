    Speed vs. Quality — Should we skip image preprocessing to make the app faster?

    Option A — Speed

    COMPUTER CRIMES & RISKS

    Risks Specific to Ocular

    Four threats we identified and actively mitigated

    Risk 1

    Sensitive Data Theft

    User uploads a medical or legal document image. If intercepted, the raw image content is exposed.

    Mitigation: Processed entirely in local memory. No temporary files written to disk. API requests use HTTPS.
    Risk 2

    Misuse of OCR Output

    Automated document conversion could be used to falsify records or extract text without consent.

    Mitigation: Confidence score + AI label on every result. Discourages use of low-confidence outputs for official purposes.
    Risk 3

    API Key Compromise

    If the OpenAI API key leaks (e.g., committed to a public repository), it enables unauthorized API usage at the owner's expense.

    Mitigation: Key stored exclusively in .env file — never in source code, never committed to version control.
    Risk 4

    Over-Reliance on AI Output

    Users may accept AI-generated text as ground truth, even when the document was noisy or handwritten.

    Mitigation: Transparency header in every .docx output: confidence score + "AI-assisted" disclosure label.

    TECHNICAL LIMITATIONS OF PHASE 1

    Why Phase 1 Was Not Enough

    Static logic cannot adapt. Intelligence requires more than rules.

    🔧

    Static Logic

    Every document was processed with the same fixed pipeline. A blurry photograph and a clean scan were treated identically — with predictably poor results for the blurry one.

    ❌

    No Autonomy

    The system could not decide whether to apply denoising or skip it. It could not decide whether to call an external model. Human had to do everything manually.

    🚫

    No Learning

    Phase 1 had no memory. Every run was completely stateless. User feedback was discarded. Poor outputs on the same document type would repeat indefinitely.

    AGENTIC SYSTEM CONCEPT

    What Makes a System "Agentic"?

    Four properties that transform a tool into an agent

    👁️

    Perception

    The agent observes its environment. In Ocular: the PerceptionAgent preprocesses the image and extracts OCR data — making the raw input understandable.

    🧠

    Decision-Making

    The agent reasons about what to do next. In Ocular: the AnalysisAgent decides whether to enhance the image and what GPT-4o query to make.

    ⚡

    Action

    The agent takes an action based on its decision. In Ocular: the FormattingAgent and DocumentAgent produce a structured, formatted Word file.

    📚

    Learning

    The agent retains experience. In Ocular: the MemoryAgent stores confidence history in SQLite and adapts processing based on past results.

    AGENT TYPE SELECTION

    Why Goal-Based + Learning Agent?

    Choosing the right agent classification for Ocular

    Simple Reflex Agent

    REJECTED

    Condition → Action only. Cannot handle noisy or ambiguous documents. No memory. No planning. Phase 1 was essentially this.

    Fully Autonomous Agent

    REJECTED

    Too risky for document processing. A fully autonomous agent could generate or modify content without any human oversight — unacceptable for accuracy-critical applications.

    Goal-Based + Learning Agent

    CHOSEN ✓

    Has a clear goal (accurate formatted document), makes decisions to achieve it, and improves over time through stored feedback. Human remains in control.

    Pure Utility Agent

    NOT FIT

    Optimises a utility function only. Document formatting requires multi-objective reasoning — accuracy, readability, and user preference simultaneously.

    Justification: Goal-based agents act with purpose rather than reflex. Adding the learning layer means Ocular's accuracy improves with each document processed — without requiring a complete redesign.

    OPERATIONAL WORKFLOW

    Observe → Interpret → Decide → Act → Learn

    The five-step cycle that runs for every document Ocular processes

    • 1

      Observe

      PerceptionAgent loads the image, applies preprocessing (denoise, deskew, threshold), runs Tesseract OCR, and extracts layout metadata.

    • 2

      Interpret

      AnalysisAgent sends image + OCR text to GPT-4o Vision. Receives structured JSON: paragraph types, alignments, bold/italic, confidence score.

    • 3

      Decide

      If confidence < 60 → AnalysisAgent decides to re-enhance the image before final output. Orchestrator coordinates the conditional branch.

    • 4

      Act

      FormattingAgent maps types → Word styles. DocumentAgent generates the .docx with coloured headings, correct spacing, and a transparency footer.

    • 5

      Learn

      MemoryAgent writes result, confidence, and processing time to SQLite. User 👍/👎 feedback stored for future preference adaptation.

    INTELLIGENCE LAYER

    Three Tiers of Intelligence

    Graceful degradation — higher tiers attempted first, lower tiers as fallback

    🧠 LLM — GPT-4o Vision Highest intelligence — context + structure
    ↓ fallback if API unavailable
    Computer Vision — OpenCV Layout features, line detection, deskew
    ↓ fallback if CV insufficient
    Rule-Based Heuristics Paragraph detection, ALL CAPS → heading, etc.
    Key insight: By having three tiers, Ocular degrades gracefully. No internet? No problem — OpenCV + rules still produce a reasonable document.
    MEMORY & CONTEXT

    Short-Term vs. Long-Term Memory

    Ocular maintains state across processing steps and across sessions

    SHORT-TERM

    Session Memory

    Type: Python dict (in-memory)
    Lifetime: Current processing session only
    Stored: Current image path, current OCR result, current analysis JSON, progress state
    Purpose: Pass context between agents without re-running expensive operations
    memory.store_session("ocr_text", result)
    memory.get_session("ocr_text")
    LONG-TERM

    Persistent Memory

    Type: SQLite database (data/memory.db)
    Lifetime: Persists across all sessions
    Stored: Image name, OCR confidence, user feedback (👍/👎), processing time, user preferences
    Purpose: Learn from history, improve future runs
    Table: processing_history
    Table: user_preferences
    Method: get_avg_confidence()

    ETHICAL AGENT DESIGN

    Building an Ethical Agentic System

    Four principles embedded into Ocular's architecture

    🔒

    Privacy

    No document images stored on disk. No external sync. API key in .env only. User content never leaves the local session without explicit action.

    Implementation: In-memory base64 encoding, no temp files, .env API key
    ⚖️

    Bias Mitigation

    Rule-based fallback ensures consistent output even when the AI model produces low-confidence results. No user group receives only failed outputs.

    Implementation: Confidence threshold (60/75) triggers fallback universally
    🔍

    Transparency

    Every output .docx includes a confidence score header. The explainability log shows every agent decision with timestamps. Nothing is hidden.

    Implementation: get_explainability_report() in logger.py — full decision trail
    🎮

    User Control

    Five human-in-the-loop control points ensure the user retains authority over every significant decision the system makes.

    Implementation: File picker → output path → feedback buttons → log export
